# Native door, ready dim and countdown references

These findings come from the cached authorized original `GameAssembly.dll`, IL2CPP metadata and level-1 scene. They are source references, not screenshot or complete physics-parity claims.

The passenger door already has the original hinge origin in `car.glb`. `CabinDoor.ResolveDoor` (RVA `0x4E6A00`) finds `BodyVisual/door_rf_ok` and caches its local rest rotation. It does not create a separate hinge or reparent/recenter the mesh. `LateUpdate` (`0x4E5610`) applies `rest * Euler(0, openSign*shownAngle, 0)`; serialized `openSign=-1`, `maxAngle=90`. Reflecting Unity X into browser coordinates reverses the Y rotation, so the browser uses `doorRest * rotationY(+clamp(angle,0,90))`. The previous negative browser sign rotated the rear edge into the cabin. With the actual exported geometry, its centroid moves from closed body-local X `-0.7858` to `-0.3100` at the incorrect negative 45 degrees, versus outward X `-1.2869` at positive 45 degrees. The original pivot remains `[-0.828998,0.666817,0.751921]` under `BodyVisual`, with source scale 100 and the exported rest quaternion unchanged.

`StageReadyOverlay.Build` assigns the fullscreen `Dim` Image a **literal** RGBA `[0.05,0.04,0.03,0.62]` at RVA `0x54A0C7`. It does not use the opaque global `GameUiColors.Backdrop`. Earlier ready metadata incorrectly copied that global value; `export_ready_titles.py` and `ReadyTitles.json` now record the actual translucent call-site color. The central panel still uses the native `GameUiColors.Panel` `[0.08,0.075,0.07,0.96]`. This leaves the map/world visible around the panel.

`StageController.BeginCountdown` (`0x529B50`) and `Update` (`0x52B140`) establish **five one-second digits, 5 / 4 / 3 / 2 / 1**, then native racing digit 0. The cached game metadata has no `StageCountdownPopup` or `CountdownOverlay` type; its 76 decompiled game classes have no such screen-popup builder. Level 1 has no countdown-named scene object, and its only serialized Canvas is `PauseCanvas`. `TabletMinimap` reads the native digits for its in-world timer. No native centered screen-countdown layout, font size, screen position, or visible `GO` label was recovered.

The user requested a visible screen countdown. `tools/export_countdown_titles.py` supplies five small white-alpha masks composed from the original Anton atlas and the exact native timing contract. Its generated `CountdownTitles.json` explicitly distinguishes recovered glyph artwork/timing from user-requested browser screen presentation. It exports no `GO` text and does not change timing or protocol. Outputs are ignored `web/public/assets/ui/Countdown5.png` through `Countdown1.png` and `CountdownTitles.json`; the original car assets and existing masks are untouched. All five PNGs were checked for valid RGBA, nonempty alpha and matching recorded SHA-256. Rendering and layout still require the owning client's verification.

The native `GoofyCarController` exposes global braking/coasting and grip settings based on speed, throttle and handbrake, plus suspension/ground contact. Its recovered configuration has no grass/offroad/terrain-splat drag or grip fields. No support for the browser's explicit extra offroad drag-4/grip-5 rule was found in the inspected controller path. Removing that browser-only rule follows the user's explicit instruction; terrain slope/contact and overall vehicle simulation remain separate fidelity questions.

Original glyphs and scene assets remain Stellux Interactive content under the project owner's stated developer permission and are excluded from the source-code MIT license. Only recipes and reference documentation belong in the source commit.
