# Original physical cockpit export

Run `.venv-build/bin/python tools/export_cockpit.py` after the normal web-asset export. It writes ignored `web/public/assets/cockpit.json` and `fonts/NativeCockpit.typeface.json`, without rewriting `car.glb`, `tablet.glb` or their materials. Original model/glyph content remains Stellux Interactive content under the project owner's stated developer permission, excluded from the source-code MIT license. The complete original Share Tech Mono outlines retain their OFL license reference and use a derivative family name.

The existing car GLB already contains the authored `ClusterGauges`, `Speedo`, `Tach`, dial faces/rims/ticks and both `NeedlePivot` meshes. The former browser runtime left the needles static. Eight serialized Unity `TextMesh` components exported as empty transform nodes, because their generated text mesh was unavailable in the static scene export. The supplemental metadata supplies their actual values, fonts, character sizes, anchors, transforms and colors so a runtime binder can restore them on the original geometry.

| Native component setting | Value |
| --- | ---: |
| Needle start / end angles | 120 / −120 degrees |
| Speedometer maximum | 160 km/h |
| Tachometer maximum | 9000 RPM |
| Needle follow rate | 14 per second |
| Steering-wheel visual maximum | 110 degrees |
| Steering-wheel local axis | `[0,0,1]` |

Native `DriverClusterGauges.LateUpdate` at RVA `0x50A490` smooths displayed speed/RPM with `1-exp(-14*dt)`. The speed source is planar rigidbody-velocity magnitude times 3.6, including sideways drift, with a network fallback. `SetNeedle` (`0x50AF40`) replaces native local rotation with Z `-lerp(120,-120,clamp(display/max))`; after the export's X reflection, the browser uses **positive** `lerp(120,-120,clamp(display/max))` degrees around Z. The readout uses rounded displayed speed. `CarAudio.OnLimiter` (`0x5335D0`) is `_limiterVol>0.05`; while active, the tach needle dips by `250+850*clamp(abs(sin(time*21))*abs(sin(time*52)),0,1)` after smoothing. The separate serialized fullscreen `DriverSpeedometer` is not enabled or reconstructed by this physical-cluster export.

The original labels are `km/h`, `x1000`, dynamic readout `0`, and speed markings `0 / 40 / 80 / 120 / 160`. Their source font is `ShareTechMono-Regular`. The packed native `TextMesh` Color32 presents reversed channels through UnityPy's `ColorRGBA` helper; reversing those channels gives actual warm-gold RGBA `[0.858824,0.721569,0.419608,1]`, consistent with the source tick color. The new metadata corrects that byte order. It records the source parent paths and existing transforms; text geometry must also receive the export's X reflection before attachment. Its Three font-size conversion is `fontSize*characterSize/10*72/100`, matching the supplied typeface normalization. The full 267-glyph JSON includes all original Unicode cmap entries and all cockpit labels; it adds no remote font dependency.

The native `GoofyCarController` wheel maximum is verified directly in source component 40316: the steering-wheel Transform 18376 PPtr is at serialized byte offset 492, followed by float values `[110,0,0,1]` for maximum angle and axis. A generic 190-degree fallback in a hand helper is not the original scene setting. Existing native wheel and tablet meshes should be retained. The serialized tablet cube is 0.24×0.018×0.28 m, but `TabletShell.Awake` changes its scale to **0.26×0.052×0.32 m** and builds fourteen additional parts at startup. `tools/export_tablet_shell.py` captures the pinned native function's primitive transforms and materials, including the four corner bumpers, raised screen lips, recessed screen well, worn corner/scuff and side button. The browser applies that construction before laying out its screen and timer; the screen offset depends on the new thickness. A static GLB export alone misses this entire assembly.

The native renderer also separates the world and cockpit. Main Camera URP component 40331 is a Base camera with postprocessing enabled and a stack containing `CarCabinOverlay` and `HelmetOverlay`. Both overlays have postprocessing disabled. Serialized solid cockpit meshes (`WheelRide`, `ClusterGauges`, doors/body) use layer 8; in-world tablet/screen use layer 10. `CarCabinOverlay` includes layers 8/10/16. The windshield is a special case on layer 0, rendered with the base/world view. Native `CabinMotionBlurExclude` maintains these layers and cameras. The world VolumeProfile 335 selects active **Neutral** tone mapping (mode 1; native enum None=0, Neutral=1, ACES=2), but the cabin overlay bypasses that postprocessing. This supports preserving flat cabin colors while treating windshield rendering separately. Source reflection settings use the skybox, 128-pixel resolution, intensity approximately 0.95 and one bounce; original Lit wheel/tablet materials need that environment response for fidelity. Renderer implementations still require visual comparison rather than assuming identically named tone mappers match.

`native-cockpit-asset-verification.json` records source/output hashes, the unchanged original car GLB hash, eight text references, corrected colors and availability of all label glyphs. These are export-integrity checks. Runtime needle motion, text orientation, reflection appearance and screenshot parity remain separate verification work.

## Local parity preview

The following supplemental exports are required for the current local renderer:

```sh
.venv-build/bin/pip install -r tools/cabin-asset-requirements.txt
.venv-build/bin/python tools/export_tablet_shell.py
.venv-build/bin/python tools/export_cabin_surfaces.py
.venv-build/bin/python tools/export_navigator_rig.py
.venv-build/bin/python tools/export_cockpit.py
```

These write ignored licensed assets under `web/public/assets`. The tablet exporter checks the original GameAssembly SHA-256 before using its fixed function addresses and emulates only the shell arithmetic with stubbed engine calls; it never launches the original game. Re-exporting reproduces all fourteen transforms/materials exactly. The navigator exporter preserves the four original skins, joints and inverse binds rather than moving bones on baked geometry. Runtime tablet holding follows the native three-pass bake, two-pass solve and tablet-local wrist mirror, returning to the serialized seated pose on release. The browser analytical chain solver preserves bone lengths.

The surface exporter also recovers the actual baked 128px reflection cube from `sharedassets0.assets`, path ID18. It preserves HDR values in six linear RGBA16F faces instead of deriving a replacement probe from background PNGs. The RGBM decoding follows Unity's [HDR environment decoder](https://github.com/Unity-Technologies/Graphics/blob/master/Packages/com.unity.render-pipelines.core/ShaderLibrary/EntityLighting.hlsl) and [linear RGBM range](https://docs.unity.com/en-us/engine/6000.5/manual/lighting-overview/direct-and-indirect-lighting/lightmap-data/lightmaps-technical-information). All eight native mip levels are decoded and retained. The renderer samples the original roughness LOD directly instead of generating a Three PMREM. Original per-material reflection/highlight flags are honored. The custom `RollingWreck/BodyBothSides` paint uses its recovered Lambert/specular expression and 45% ambient desaturation/warming rather than generic glTF PBR.

Reference screenshots: [developer Steam gallery](https://store.steampowered.com/app/5362020/). The gallery shows an earlier blank instrument panel; the pinned compiled game contains the physical gauges, so its actual meshes, eight labels and needle settings are retained. The original constructor's gold route/orange marker artwork matches the gallery; the compiled level1 includes white/grey scene overrides. The preview deliberately uses the reference artwork, while retaining authored route geometry and held anchors. These version differences prevent calling the whole image pixel-identical.

`web/cockpit-qa.html` is a local inspection tool. Instrument close-up hides wheel/driver geometry and zooms solely for inspection; it does not alter gameplay. Captures and test reports are under ignored `local/visual-parity/`. The playable verification build is isolated in `local/cockpit-preview/`. The user authorized deployment after verification; `local/cabin-release/client/` contains the same-origin release artifact. Publication copies assets first and switches the live index atomically, retaining old bundles and leaving the server/tunnel running. No Git push is part of this release. The user's larger wiper control is intentionally retained.


## Lighting, glass and animation verification

The source `CarGlass` pixel program's clean-glass interval (28–290) supplies its premultiplied base tint, eighth-power grazing highlight, source smoothness exponent, highlight clamp and alpha response. `native-glass-fixtures.json` contains independently evaluated DXBC results, including back faces; the CPU implementation is checked against these samples. The mud material chains this shader before applying the existing native mud mask and swept clearing areas, retaining original knob rotation (420 degrees/second) and 95-degree/0.45-second wiper strokes. Source colors and floats are exported in `cabin-surfaces.json`. Metadata fetches revalidate to prevent a cached older schema from breaking a new client.

The world and glass now render to a linear target; the original Neutral curve and vignette run before the unprocessed cabin overlay. The vignette precedes tone mapping, following Unity's [UberPost ordering](https://github.com/Unity-Technologies/Graphics/blob/master/Packages/com.unity.render-pipelines.universal/Shaders/PostProcessing/UberPost.shader). The direct/environment surface response follows the original metallic workflow rather than Three's multiscattering model; see [Unity's BRDF reference](https://github.com/Unity-Technologies/Graphics/blob/master/Packages/com.unity.render-pipelines.universal/ShaderLibrary/BRDF.hlsl) and [Neutral color curve](https://github.com/Unity-Technologies/Graphics/blob/master/Packages/com.unity.render-pipelines.core/ShaderLibrary/Color.hlsl).

Comparison used the original runtime transforms/materials and developer gallery images, not an assertion of complete pixel identity. The gallery uses an earlier panel/tablet version and moving cameras, while static captures here use the pinned newer runtime. Remaining differences include approximate gradient ambient rather than Unity SH, approximate native iterative sphere fitting, omitted native bloom, and unverified complete animation equivalence. These remain explicit visual parity limits. Steering, tablet holding/release, clean/muddy glass, wipe return, gauges and both player views were inspected locally. Test logs and screenshots are in `local/visual-parity/`. Multiplayer acceptance uses two independent clients on one Mac; it does not establish two physical laptops or every network's performance.


## Shadows and camera motion blur

The new `shadows` and `postprocessing.motionBlur` metadata comes from the pinned runtime, not tuned by eye. `PC_RPAsset` (`globalgamemanagers.assets:2805`, serialized URP layout v13) selects four cascades, a 2048px atlas (four 1024px tiles), 160m distance, split fractions 0.12299999/0.29260001/0.53599995, border 0.10775860 and high soft-shadow quality. The legacy QualitySettings distance is 95m; the active URP asset overrides it. Source Sun strength is 0.92, depth bias 0.035, normal bias 0.30 and near plane 0.20m. The exporter validates the asset version and layout before reading the fields and records source hashes.

`native-shadows.js` now uses world-space spherical cascade selection and native shadow projection rather than Three CSM's default depth-slice fitting. A read-only plugin captured six original Unity 6000.3.16f1 projection/sphere fixtures at different FOVs, aspect ratios and positions. Given those source spheres, the reconstructed projection matches all six matrices with maximum element error 1.483e-7: radius guard band `1+10/1024`, floored world-texel snapping, depth span `2.2*r+2`, and depth-center offset `+1`. Fixture 3 is valid for matrix-from-sphere checks but its rotation metadata changed after the native render callback, so it is excluded from frustum-fit comparison.

The browser reconstructs float32 camera clip depth and uses analytic frustum spheres. The original uses a proprietary 64-iteration conservative enclosing-sphere solver; across five valid near-cascade fixtures, current center/radius differences are below 0.27m/0.125m (largest at ultrawide FOV). Thus the projection function is captured/verified, while complete projected silhouettes are still approximate. The numeric fixtures are in `web/client/fixtures/native-shadow-matrices.json`; raw probe output stays under ignored `local/shadow-oracle/`.

High-quality filtering integrates a seven-texel tent into sixteen bilinear comparison fetches, following [Unity's tent geometry](https://github.com/Unity-Technologies/Graphics/blob/master/Packages/com.unity.render-pipelines.core/ShaderLibrary/Shadow/ShadowSamplingTent.hlsl). Bias now offsets actual caster vertices, including skinned/instanced geometry, with native light/normal incidence response, source raster bias and near-plane pancaking. Exported renderer flags restore original cast/receive behavior; native glass does not cast. Receiver bias is zero. Squared camera-distance fade retains the source border. These improvements do not establish complete pixel identity between Unity and WebGL.

`MotionBlur` (`sharedassets1.assets:338`) selects CameraOnly, Medium, intensity 0.22 and clamp 0.05. The [source camera-blur algorithm](https://github.com/Unity-Technologies/Graphics/blob/master/Packages/com.unity.render-pipelines.universal/Shaders/PostProcessing/CameraMotionBlur.shader) reconstructs world position from depth, projects into the previous camera and gathers six jittered point-clamp samples. The browser follows that NDC velocity convention, including clamp-before-intensity. It runs before vignette/Neutral and before the sharp cabin overlay. There is no accumulation of previous color frames, avoiding trailing cockpit ghosts.

History resets on stage/retry, seat changes, tab resume, resize, discontinuous camera motion and long frame gaps. Menus skip redundant cascade updates. Graphics-quality changes invalidate cached material shaders; disabling shadow-map updates alone does not remove an already compiled shadow lookup.

Verification: 145 tests; matched-frame GPU blur A/B changed forest/road pixels while sampled wheel/hand (25,200px), dashboard (6,300px), tablet (9,100px) and hood (4,000px) regions remained byte-identical. Shadow strength A/B changed 480,469 image pixels below the toolbar, proving actual shadow contribution. Shader errors were absent in local GPU checks. Moving local QA samples reported approximately 55–80fps at the inspection viewport; that is not a guarantee for every device. Production-stage screenshots, numerical comparisons and multiplayer reports are under `local/visual-parity/`. The official gallery remains a qualitative composition/reference check because it is an earlier game version and different moving frame. Bloom, exact SH ambient, complete animations and engine-level pixel identity remain outside this pass.


### Persistent cross-network endpoint (2026-11-14)

Production Vercel now configures `VITE_GAME_SERVER` and `GAME_SERVER_ORIGIN` to the user-enabled Tailscale Funnel hostname. The client opens WSS directly to the existing authoritative Node game server, avoiding the old per-input HTTP/D1 route. Any HTTP fallback targets the same authority, preventing split rooms; the current Node service is WebSocket-only for gameplay, so blocked WebSockets cannot silently fall back to the old room service.

The public Funnel route was tested with two independent clients on this Mac, overriding local MagicDNS to use a real public relay. Independent Globalping HTTP probes reached `/health` from Mumbai, Bengaluru, Falkenstein and Nuremberg. These establish reachability, not a real two-country gameplay test. India–Germany geographic latency remains; the server still runs on this Mac and requires it to stay awake and connected. This is not dedicated regional hosting. Old HTTP rooms must be recreated after both players reload.

Brave verification after user-approved local-network access: selected "Allow" with decision lifetime "until I close this site". Two Vercel tabs created/joined the same room, readied both players, counted down, drove, crashed and returned to the running scene after R restart. Both clients were on this Mac. Tailscale MagicDNS on the hosting Mac triggers this browser permission; the same-origin direct public game link also remains available.
